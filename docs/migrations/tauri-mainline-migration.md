# Tauri mainline migration

- Status: In progress
- Architecture status: Accepted, not experimental
- Start date: 2026-08-02
- Working branch: `codex/tauri-mainline-migration`
- Starting commit: `66e398fa6256f17b04c82569e6764a9e5332265c`
- Frozen native tag: `native-baseline-before-tauri-2026-08-02`
- Frozen native repository:
  `https://github.com/Dokpamo/lorepia-native-reference`

## Outcome

Lorepia's main product client is the Tauri 2 application at `apps/lorepia`.
Android, iOS, macOS, and Windows use one Svelte 5 and TypeScript product UI over
the preserved Rust Core. Platform-native code remains behind narrow Tauri
plugins where an OS security or lifecycle boundary requires it.

This plan does not decide whether to adopt Tauri; that decision is already
Accepted in
[ADR-0006](../architecture/decisions/ADR-0006-adopt-tauri-primary-client.md).
Its gates determine when the mainline is safe to release and when superseded
native source is safe to remove.

## Scope

The migration includes:

- a packaged, non-SSR Svelte 5, strict TypeScript, and Vite frontend;
- a Tauri 2 shell for each supported platform;
- a typed `shell-api` adapter over the current Core contract;
- scoped native integrations for credentials, file picking, lifecycle,
  notifications, deep links, and menus;
- ordered chat streaming and persisted-state reconciliation;
- Library, Import, conversations, Chat, branch and message actions, Provider
  Settings, discovery, model synchronization, and signed catalog parity;
- data-root, database, asset, and credential continuity;
- release configuration, signing, packaging, upgrades, platform CI,
  accessibility, IME, lifecycle, and performance validation; and
- removal of superseded native UI source only after all removal gates pass.

## Explicit non-goals

This migration does not:

- rewrite the Rust Core;
- add cursor pagination because the UI framework changed;
- replace `expected_head` with `expectedRevision`;
- invent new Core events and label them existing behavior;
- move provider networking or package parsing into JavaScript;
- add a backend, account system, cloud sync, billing, marketplace, or remote
  application frontend;
- implement Creator Runtime or Creator Studio as a migration gate; or
- implement downloaded JavaScript, remote HTML, `script-v1`, creator network
  access, creator filesystem access, creator native access, or creator Tauri
  IPC.

Creator work is tracked separately in the
[Creator platform roadmap](../roadmaps/creator-platform-roadmap.md).

## Contract-preservation rules

The initial Tauri boundary maps the baseline contract:

| Contract | Baseline |
|---|---|
| Core API | version 8 |
| UniFFI API | version 8 |
| C ABI | version 7 |
| Chat event | version 4 |
| Character and conversation listing | Core-owned `Vec` results, no cursor |
| Message concurrency | branch `expected_head`, no synthetic revision |
| Generation stream | generation/conversation/branch/message identity plus monotonic sequence |

The full method-level evidence is in
[core-tauri-contract-matrix.md](core-tauri-contract-matrix.md). `shell-api`
defines only the UI projection needed for a command, validates input, removes
secret or path fields, produces a stable redacted error envelope, and reconnects
frontend state to persisted Core state. The Tauri application adapter composes
that API with the minimum scoped platform-plugin operation. Neither becomes a
second domain layer.

Normal request/response operations use Tauri commands. High-rate chat events
use an ordered Tauri Channel, never a global string event bus. A receiver
validates event version, generation, conversation, branch, assistant message,
sequence, lifecycle epoch, and terminal state. It rejects or reconciles wrong,
duplicate, decreasing, stale, detached, post-terminal, or unsupported events.

The first valid routed event must have a non-null assistant message ID, which
then remains stable. Send, edit, and regenerate obtain their Core receiver
before starting the generation. Every such receiver has a canonical UUID in a
bounded backend registry. Explicit receiver disposal, view replacement,
reconciliation, and controller destruction stop the matching adapter task and
listener; the slot remains counted until that task exits. They do not cancel a
Core generation unless the user explicitly requested cancellation. Broadcast
lag, dropped delivery, background/foreground transitions, and restart
reconcile from persisted messages and pending generation state.

Same-process reattachment is deliberately unavailable in the production Tauri
path. The registered `subscribe_generation` command has no application state
and returns the stable, nonrecoverable
`generation_reattachment_unavailable` error before registry admission or any
Shell/Core call. The frontend does not invoke it during persisted restoration
or reconciliation. If the persisted generation remains pending, the UI shows a
localized blocking alert, retains the generation ID for explicit cancellation,
and keeps new send, edit, and regenerate starts disabled.

Core still has no atomic operation that validates the live
generation/conversation/branch route while returning status, a sequence
watermark, and an already-established receiver. Keeping reattachment disabled
makes the prior persisted-read/subscription terminal gap and invalid-ID
capacity exhaustion unreachable through production Tauri. Before re-enabling
the feature, Core must provide that atomic contract or a durable outbox with
equivalent no-gap semantics, and unknown, terminal, or wrong-route cases must
fail before registry admission.

## Platform continuity

Development builds use separate platform identities and can coexist with the
native apps. Production release builds retain the established Android and Apple
application identities and compatible signing lineage. The baseline Windows
app is unpackaged and defines no installer upgrade identity, so Tauri's
source identifier `dev.lorepia.windows` is configured but its production package
or installer identity, signing lineage, and continuity must still be
deliberately established, documented, and then kept stable.

Production source versioning is monotonic over the frozen native baseline:
Android `versionCode` and the iOS/macOS `bundleVersion` are `2`, while the
corresponding native build value is `1`. Packaged artifact inspection and a
signed update run are still required; configuration alone is not an accepted
upgrade.

Tauri must use the exact roots and credential formats in
[native-baseline.md](native-baseline.md), not framework-default paths:

- Android Core root at `context.filesDir/lorepia-data`;
- iOS and macOS Core root at Application Support plus `LorePia`; and
- Windows Core root at `%LOCALAPPDATA%\\LorePia`.

Android import uses `ACTION_OPEN_DOCUMENT`, a read-only URI grant, and a
bounded app-private transport copy. That flow does not need a `FileProvider`,
but Tauri's generated WebView uses one for an explicit camera-capture chooser.
The checked-in provider is non-exported and restricts URI grants to the
app-owned external-files `Pictures/` directory; general external, cache, files,
and root paths are forbidden. Clean regeneration and packaged APK inspection
must prove that exact restriction before release.

Credential operations stay in the platform layer and preserve the existing
Keystore alias and encrypted record, Keychain service/account/accessibility,
and PasswordVault resource/user-name rules. JavaScript receives availability
state only. Credential writes and Core mutations preserve the existing
in-process compensating-transaction behavior. This does not make the initial
vault write plus Core commit crash-safe. Before production cutover, a separate
durable Core/storage credential-install intent/outcome state machine must
reconcile on startup and pass crash/failure-injection tests. The provider
discovery `Compensating` state is post-failure cleanup and is not that journal.

The iOS Swift Keychain backend reads and verifies the exact
`WhenUnlockedThisDeviceOnly` attribute and restores the prior record after a
reported update failure. The macOS Rust backend now requests and decodes the
returned accessibility, hardens nonconforming records, verifies the exact value
and required attribute, restores the exact prior record after a reported
failure, and uses `SecItemUpdate` for an existing item rather than pre-deleting
it. The current 23-test Rust plugin suite passes on the macOS host. Before
macOS production cutover, real system-Keychain, signed-continuity, and targeted
mutation/verification/Core commit interruption behavior must still be proven.
The shared durable
credential-install lifecycle above remains a separate code gate.

Import preserves the existing trust boundary:

```text
native picker
  -> bounded app-owned transport copy
  -> Rust inspection snapshot
  -> structured review
  -> explicit commit or discard
  -> transport cleanup
```

The frontend receives logical asset identifiers and bounded metadata, never the
unrestricted source path.

## Implementation sequence

### 1. Bootstrap and contracts

- establish the real Tauri/Svelte application and locked toolchain;
- open and close the live Core at the preserved data root;
- expose health, version, startup failure, and graceful shutdown behavior;
- implement typed error redaction and capability separation; and
- complete the current Core/UniFFI/C ABI/Tauri contract matrix.

### 2. Library and Import

- list and inspect characters;
- use the native picker and bounded transport staging;
- render inspection warnings and blocked reasons;
- commit or discard explicitly;
- render safe asset metadata; and
- prove restart persistence and loading, empty, and error states.

### 3. Conversations and Chat

- list, create, and open conversations;
- preserve chat/story mode, active branch, and message history;
- send with ordered reasoning, text, usage, and terminal events;
- cancel explicitly;
- edit, regenerate, and remove with `expected_head`;
- create and select branches;
- preserve selection, copy, and long-message interaction; and
- restore pending work and reconcile lag, process restart, and lifecycle
  transitions.

### 4. Provider lifecycle

- migrate templates, connections, routes, presets, and selected target;
- implement credential create, status, update, delete, and compensation;
- add the separate durable credential-install intent/outcome state machine,
  startup reconciliation, and crash/failure-injection coverage;
- render Core-owned parameters, reasoning, cache controls, validation, and
  redacted request preview; and
- complete provider discovery, user-consent boundaries, durable resume, model
  synchronization, diff/review/apply, observations, and signed catalog
  import/activation/rollback.

### 5. Platform release hardening

- complete native plugins without widening capabilities;
- configure development and production identities;
- validate signing, packaging, installation, launch, update, and rollback;
- run IME, accessibility, lifecycle, and performance scenarios; and
- make hosted CI authoritative for platforms unavailable on the current host.

### 6. Native source removal

Only after every removal gate passes, remove the superseded Android, Apple, and
Windows UI applications in a separate commit. Remove their app-only CI and
wrappers only when no Tauri or contract test uses them. Clean up UniFFI and the
C ABI later, in another commit, after all runtime references are gone and
equivalent Tauri-boundary coverage exists.

## Production-release gate

Every item below requires recorded evidence. A missing host, pending CI job, or
started test is not a pass.

- Tauri Android, iOS, macOS, and Windows builds install and launch.
- Library and Import match the frozen native behavior.
- Conversations, Chat, branches, edit, regenerate, removal, cancellation, and
  pending-generation recovery match.
- Reattachment uses a Core-owned atomic status/watermark subscription or durable
  outbox, cannot miss a terminal event between persisted reconciliation and
  listener setup, and rejects unknown, terminal, or wrong-route generations
  before consuming bounded stream capacity.
- Provider Settings, discovery, model synchronization, and signed catalog
  lifecycle match.
- Existing Core data roots open in place.
- Native-seeded synthetic databases, assets, selected routes, and presets
  survive the update.
- Android, Apple, and Windows native-seeded synthetic credentials remain
  usable without entering JavaScript.
- Credential installation and matching Core mutation survive every injected
  crash boundary and reconcile from the durable pre-install state on startup.
- macOS Keychain reads verify the exact accessibility attribute, replacement
  uses the no-pre-delete update path, and the prior protected item survives
  every injected Keychain mutation, verification, restoration, and matching
  Core-commit interruption boundary.
- Korean, Japanese, and Chinese IME composition, multiline editing, selection,
  mobile keyboard, back behavior, safe area, gestures, and desktop shortcuts
  pass.
- Keyboard navigation, focus, labels, text scaling, contrast, reduced motion,
  VoiceOver, TalkBack, Narrator, and macOS accessibility smokes pass.
- Long-chat virtualization bounds the visible DOM and preserves scroll anchors.
- At least 10,000 synthetic messages, 4,096 ordered stream events, 100 repeated
  send/cancel or regenerate/cancel cycles, background/resume, restart, lag
  recovery, terminal-at-every-reattachment-boundary, invalid-subscription
  saturation, and scroll stability are measured on recorded devices and
  runners.
- No credential, authorization header, private prompt, unrestricted path, or
  unredacted platform failure appears in state, events, logs, or errors.
- Rust, frontend format/type/lint/unit/component/build, dependency policy,
  `shell-api`, command validation, redaction, ordering, disposal, integration,
  upgrade, and all relevant platform CI checks are green.
- Production signing, installer/update identity, data protection, and rollback
  procedure are documented and exercised with synthetic fixtures.

## Native-source-removal gate

The production-release gate above must pass, and all of these additional facts
must be recorded before deleting native source:

- the frozen repository remains private, cloneable, and complete;
- its `main` and annotated tag still peel to
  `66e398fa6256f17b04c82569e6764a9e5332265c`;
- build instructions and synthetic upgrade seed harnesses remain available;
- all supported platform CI is green on the removal candidate;
- no active runtime or release pipeline points at the old app; and
- documentation and developer entry points identify `apps/lorepia` as the
  sole product client.

Passing the mirror check alone never authorizes deletion.

## Upgrade and rollback fixture

For each platform:

1. use the frozen native harness to seed a synthetic database, assets, route,
   preset, conversation history, and synthetic credential;
2. install or update to the Tauri build with the production test identity;
3. verify the database, assets, selected route, preset, and credential
   availability;
4. make a synthetic authenticated request without exposing the secret to
   JavaScript;
5. where supported, verify a Tauri-written synthetic credential with the native
   harness;
6. exercise rollback to a compatible baseline build; and
7. verify schema, WAL/SHM handling, assets, and database integrity.

Tests run only in disposable emulators, simulators, VMs, or dedicated test
environments. They never use an existing user's installation or credential.

## Security floor

- Capabilities are explicit; wildcards are forbidden.
- Development and release capabilities are separate.
- Generic shell and unrestricted filesystem access are disabled.
- Remote frontend loading, arbitrary external navigation, `eval`, and creator
  code execution are disabled.
- CSP is strict and `connect-src` is bounded.
- Provider networking and package parsing remain in Rust.
- A credential read for target-based generation remains bound to the
  Rust-selected provider connection across the native await and is checked
  against the same final validated target before provider construction or chat
  mutation.
- Same-process generation reattachment fails closed before application state,
  registry, Shell, or Core access until Core owns an atomic live-route,
  status/watermark, and receiver contract or an equivalent durable outbox.
- Provider-controlled mobile import staging uses a different serial work lane
  from Keystore or Keychain operations.
- Remote setup-assistant turns fail closed before credential access until Rust
  owns route-specific pricing, exact-request token accounting, and usage
  reconciliation.
- Clipboard writes require a direct user action.
- Error and diagnostic output is redacted.
- Tauri Isolation is not represented as a CPU or memory sandbox for untrusted
  scripts.

Any need to widen these rules stops that feature for focused threat analysis.
It does not get hidden inside a general migration commit.

# Generated code

## Tauri mainline

`apps/lorepia/package-lock.json` is the single frontend dependency lock and is
updated through npm, not by hand. `node_modules`, Vite output, Tauri/Rust build
output, native libraries, installers, and signed application bundles are build
artifacts and are not committed.

Tauri configuration, capability declarations, command registration, Channel
adapters, and `shell-api` DTOs are security-sensitive source, not disposable
generated output. Review them as code. Do not label a hand-written contract as
generated.

The current exact Tauri 2 toolchain is:

- Rust `tauri` crate `2.11.5`;
- `tauri-build` `2.6.3`;
- JavaScript `@tauri-apps/api` `2.11.1`; and
- `@tauri-apps/cli` `2.11.4`.

These components version independently; “Tauri 2” is the architecture family,
not one shared patch number.

The production-canonical Tauri mobile projects are generated by
`@tauri-apps/cli` **2.11.4**, pinned exactly in `apps/lorepia/package.json` and
`apps/lorepia/package-lock.json`. From `apps/lorepia`, regenerate them with:

```bash
npm run tauri -- android init --ci --skip-targets-install \
  -c src-tauri/tauri.release.conf.json \
  -c src-tauri/tauri.android.conf.json
npm run tauri -- ios init --ci --skip-targets-install \
  -c src-tauri/tauri.release.conf.json \
  -c src-tauri/tauri.ios.conf.json
```

Android generation requires JDK 21 and matching `ANDROID_HOME`,
`ANDROID_SDK_ROOT`, `NDK_HOME`, and `ANDROID_NDK_HOME` values. The audited
regeneration used NDK `27.3.13750724`. After generation, the committed Gradle
wrapper uses the generated Gradle `8.14.3` distribution URL. Three additional
supply-chain keys are deliberately normalized: official SHA-256
`bd71102213493060956ec229d946beee57158dbd89d0e62b91bca0fa2c5f3531`,
`networkTimeout=10000`, and `validateDistributionUrl=true`.

Immediately after every Android init, run the deterministic aftercare helper:

```bash
node ../../scripts/normalize-tauri-android-generated.mjs
node ../../scripts/normalize-tauri-android-generated.mjs --check
```

The commands above assume the current directory is `apps/lorepia`, matching the
init commands. The helper resolves paths from its own location, validates the
expected Tauri `2.11.4` non-exported `FileProvider`, replaces only the audited
generator's broad camera paths with the project-owned external `Pictures/`
path, and pins the three Gradle wrapper supply-chain properties. It stops
instead of rewriting an unknown generator shape or changed Gradle distribution.

The following generated source trees are committed and, except for the
declared deterministic Android aftercare below, are not hand-edited:

- `apps/lorepia/src-tauri/gen/android`, with production application ID
  `dev.lorepia.app` and product name `LorePia`;
- `apps/lorepia/src-tauri/gen/apple`, with production bundle ID
  `dev.lorepia.ios` and product name `LorePia`; and
- `apps/lorepia/src-tauri/permissions/autogenerated`.

The helper may normalize only `file_paths.xml`, `distributionSha256Sum`,
`networkTimeout`, and `validateDistributionUrl`. The generated
`distributionUrl` and provider declaration are validation inputs, not rewrite
exceptions. Any other generated-tree change requires regenerating the owning
tree and reviewing its full diff rather than patching application or project
files. Tauri schema output under `apps/lorepia/src-tauri/gen/schemas` is
disposable and ignored.

The generated Android WebView camera chooser requires its non-exported
`FileProvider`; removing it breaks explicit camera capture. The committed
security policy restricts `file_paths.xml` to one `external-files-path` named
`tauri_capture_images` at `Pictures/` and forbids general external, cache,
files, and root paths. The checked-in helper makes this restriction
reproducible and refuses unknown generator output. It is not permission to make
arbitrary generated-source edits. A clean build must also prove the merged
manifest and packaged path resource.

The Tauri workflow is configured to run builds, compare the complete applicable
mobile generated tree and permission tree with the committed baseline, and
reject tracked drift or nonignored untracked additions caused by the build. No
hosted run is claimed here. The workflow does not perform a fresh init or prove
that an obsolete tracked generator file was removed.

The production-canonical mobile version values are also deliberate continuity
inputs, not development overlays. Android `versionCode` is `2`; iOS
`bundleVersion` and generated `CFBundleVersion` are `2`; and the macOS
`bundleVersion` is `2`. The frozen native Android, iOS, and macOS build value is
`1`. Do not normalize these production values back to `1` or change them
without updating the continuity contract and release evidence.

Development builds may apply only these asserted or observed mutations before
CI normalizes them back to the production baseline for the full-tree
comparison:

- Android `build.gradle.kts`: exactly one
  `applicationIdSuffix = ".dev"` line. Generated `strings.xml` remains
  byte-for-byte production-canonical, so the packaged development label is
  `LorePia`, not `LorePia Dev`;
- iOS `project.pbxproj`: exactly two development bundle identifiers and two
  development product names; and
- iOS source `Info.plist`: `CFBundleVersion` remains `2`, while the build may
  remove only its final newline.

iOS `project.yml` must remain byte-for-byte production-canonical during a
development build. A development bundle identifier or product name appearing
there is drift, not an allowed overlay.

The repository [`.gitignore`](../../.gitignore) together with the generated
[Android root](../../apps/lorepia/src-tauri/gen/android/.gitignore),
[Android app](../../apps/lorepia/src-tauri/gen/android/app/.gitignore), and
[Apple](../../apps/lorepia/src-tauri/gen/apple/.gitignore) ignore files are the
authority for local-only output. The generated-tree allowances are exactly:

- Android root: `*.iml`, `.gradle`, `/local.properties`,
  `/.idea/{caches,libraries,modules.xml,workspace.xml,navEditor.xml,assetWizardSettings.xml}`,
  `.DS_Store`, `build`, `/captures`, `.externalNativeBuild`, `.cxx`,
  `local.properties`, `key.properties`, `keystore.properties`, `/.tauri`, and
  `/tauri.settings.gradle`;
- Android app: `/src/main/**/generated`, `/src/main/jniLibs/**/*.so`,
  `/src/main/assets/tauri.conf.json`, `/tauri.build.gradle.kts`,
  `/proguard-tauri.pro`, and `/tauri.properties`; and
- Apple: `xcuserdata/`, `build/`, and `Externals/`.

The root ignore additionally covers the disposable Tauri schema tree and
repository-wide build/cache, Xcode user-state, binary/signing-output, editor,
and log patterns listed there. No other generated source may be silently
ignored or edited by hand.

## Frozen native bindings

The UniFFI Rust API remains the source of truth only for the frozen Kotlin and
Swift compatibility harnesses while they are retained.

```bash
./scripts/generate-bindings.sh kotlin
./scripts/generate-bindings.sh swift
```

Generated Kotlin and Swift files carry no product logic and are not edited by
hand. The generator version is locked in `Cargo.lock`; `.gitattributes` fixes
line endings. CI regenerates sources, verifies an explicit file manifest, and
fails on tracked changes, untracked additions, or stale extra files with
`scripts/check-generated-tree.sh`.

`apps/apple/project.yml` is also regenerated in Apple CI with XcodeGen 2.45.4
from its checksum-verified release archive. The committed Xcode project and
shared schemes must remain an exact result of that specification.

Native libraries, DLLs, `.so` files, static libraries, XCFrameworks, APKs, and
app packages are build outputs and are ignored.

Do not remove the binding generators or their drift checks until no parity or
upgrade fixture references them and equivalent `shell-api`/Tauri contract
coverage has passed. Their eventual removal is a separate cleanup change.
